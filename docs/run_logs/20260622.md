## Post-manual 分析链和 HTML report

今天集中处理 manual ROI 之后的数据链条和 HTML report。

### 1. 修复 trace step 缺失

最初运行 post-manual 链条时，launcher 报错：

```text
Missing script for step trace: current/analysis/10_trace_plots.py
```

因此新增并接入 trace step：

- `current/analysis/10_trace_plots.py`
- `current/run_pipeline.py` 中的 `trace` step

trace step 用于给 final ROI 生成每个 ROI 的 dF/F trace、normalized trace、overview 和 summary 表，供 report 直接引用。

### 2. 明确 downstream 只处理 manual final ROI

根据 manual ROI 语义，后续分析不应再处理原始 suite2p/cellpose 全量候选 ROI，而应只处理 manual curation 后的 final ROI。

相关逻辑：

- step 06 默认 `--roi-source manual`。
- 没有 final manual ROI 的 trial 默认跳过，而不是回退到几百个自动 ROI。
- trace/report 也以 step 06 的 manual final dF/F 为入口。

### 3. HTML report 初版完善

step 16 HTML report 从简单表格扩展为更可用的浏览界面：

- 每天的 trial report 放入日期文件夹。
- 生成 global report 作为总入口。
- 每个 trial report 包含 At a Glance、ROI Explorer、Evidence Figures、Responses、Angle、Features 和 Exports。
- ROI Explorer 使用 manual final ROI stat 画形状，避免显示原始 suite2p/cellpose overlay。
- report 中链接 trace step 生成的 ROI trace 图。

### 4. 刺激日志时间匹配

修正 step 02 对刺激日志的发现和匹配：

- 默认优先读取 `DATA_ROOT/00_stim_logs_raw`。
- 递归发现 `timestamp_log_*.csv`。
- 以时间匹配 trial 和刺激协议，而不是按文件名硬匹配。
- 输出 `stim_protocol_matches.csv`，作为后续 report 判断 stim / AoLP 的依据之一。

在 2026 Olympus 数据上重新运行 step 02 和 step 16 后，记录到的结果：

- 找到 65 个 raw stim protocol log。
- 生成 112 行 trial metadata。
- 47 个 trial 匹配到 stim protocol。
- 24 个 trial 有 numeric AoLP。
- 23 个 stim trial 没有 numeric AoLP。
- 生成 954 行 stim event。

### 5. No AoLP 初步判读

抽查部分被标记为 no AoLP 的 trial 后，发现一些 raw angle list 文件内容为：

```text
motor_disabled
[]
```

对应 `experiment_config_*.json` 中可见 `use_motor: false`。因此这类 trial 更应解释为“有刺激日志但没有实际 motor/AoLP 记录”，不能直接写成刺激匹配失败。

后续 report 应继续区分：

- 是否有刺激；
- 是否有实际 numeric AoLP；
- 是否存在计划角度序列但 motor disabled。

## 当日结论

- post-manual 链条应以 final manual ROI 为唯一 downstream ROI universe。
- report 需要同时服务数据检查和人工浏览，不应只输出空表格。
- AoLP 判读要区分实际记录和计划配置，尤其是 `motor_disabled` 的情况。
