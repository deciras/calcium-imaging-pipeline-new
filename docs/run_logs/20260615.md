### 2026-06-15 manual GUI 卡顿优化

问题：

- GUI 使用过程中会逐渐变卡，尤其是打开 suite2p refs、播放 movie、拖动 frame 或频繁捡/删 ROI 时。
- 主要原因包括：
  - 每次刷新都会重新归一化当前帧
  - 左右两幅图会重复绘制同一帧底图
  - suite2p refs 有上千个 ROI 点，每次刷新都重画全部 overlay
  - 捡/删 suite2p ROI 时会立即重算所有手画 ROI 的 trace

修改内容：

- 增加当前帧底图缓存：
  - 同一帧左右两幅图共用一次归一化结果
  - 调 brightness/contrast 或切换 movie source 时清空缓存
- 增加静态 ROI overlay 缓存：
  - suite2p refs / final ROI overlay 不随 frame 改变
  - 播放或拖动 frame 时复用 overlay，不再每帧重画上千个 ROI
  - overlay 缓存设置小上限，避免频繁点选后占用过多内存
- 手画 ROI trace 改为懒更新：
  - 捡/删 suite2p ROI 或批量清除时先标记 trace dirty
  - 只有选中手画 ROI 查看 trace 或保存输出时才重算
  - 保存前仍会强制保证 trace 最新，不改变输出正确性

验证：

- `05_manual_roi_curation_gui.py` 语法检查通过
- offscreen 启动 GUI 成功
- 打开 suite2p refs 后连续切 20 帧用时约 `0.5 s`
- 连续切帧时 overlay 缓存保持为 2 张，说明左右图复用静态 overlay 正常

### 2026-06-15 manual ROI 撤销预览线修复

问题：

- 手画 ROI 完成后执行 `Undo`，新加的 ROI 会被撤销，但刚刚画完的线仍然留在画布上。
- 需要再开始画一个新 ROI，旧线才会消失。

原因：

- `finish_polygon_roi()` 在添加 manual ROI 前会把当前绘制线保存进 undo 栈。
- 撤销 `add-manual` 时恢复了添加前状态，也把刚完成的 `current_polygon` 恢复成了动态预览线。

修改内容：

- `undo_last_action()` 对 `label == "add-manual"` 单独处理：
  - 恢复 ROI 列表到添加前状态
  - 但不恢复刚完成的 `current_polygon`
  - 同时清空 ellipse / freehand drawing 状态
- 其它撤销类型不变，例如撤销 `clear-polygon` 仍可以恢复未完成线段。

验证：

- `05_manual_roi_curation_gui.py` 语法检查通过

### 2026-06-15 suite2p ROI 尺寸参数测试

背景：

- 当前 05 输出的 suite2p ROI 候选看起来偏小
- 正式输出中 `20260428_Euprymna_retina2_25x` 的 suite2p 参数为 `diameter=[6, 6]`
- 全部候选 ROI 的中位等效直径约 `6.48 px`
- suite2p `iscell=1` 的中位等效直径约 `6.86 px`

测试方式：

- 只测试一个代表 trial：
  - `20260428_Euprymna_retina2_25x`
- 不覆盖正式输出
- 临时输入 / 输出目录：
  - `test_dataset/05_suite2p_param_tests/inputs/`
  - `test_dataset/05_suite2p_param_tests/outputs/`
- 对比 motion-corrected 与 spatial high-pass
- 对比小直径与较大直径
- 对比 `threshold_scaling=1.2` 与更宽松的 `0.8`

结果：

| config | n_roi | n_iscell | diameter | threshold | median eq diam px |
| --- | ---: | ---: | --- | ---: | ---: |
| official_current | 1298 | 343 | `[6, 6]` | 1.2 | 6.48 |
| highpass_d6_thr12 | 1298 | 343 | `[6, 6]` | 1.2 | 6.48 |
| corrected_d6_thr12 | 1289 | 329 | `[6, 6]` | 1.2 | 6.48 |
| corrected_d10_thr12 | 588 | 86 | `[10, 10]` | 1.2 | 10.22 |
| highpass_d10_thr12 | 638 | 99 | `[10, 10]` | 1.2 | 9.51 |
| corrected_d10_thr08 | 1215 | 200 | `[10, 10]` | 0.8 | 10.22 |

输出文件：

- `test_dataset/05_suite2p_param_tests/param_test_summary.csv`
- `test_dataset/05_suite2p_param_tests/param_test_overlay_montage.png`

结论：

- 只把输入从 high-pass 换成 motion-corrected，ROI 尺寸不会明显变大
- ROI 偏小的直接原因是 `diameter=[6, 6]`
- 调到 `diameter=[10, 10]` 后，候选 ROI 尺寸明显更接近预期
- `threshold_scaling=0.8` 可以保留更多候选，但运行明显更慢，且候选太密，不适合作默认
- `corrected_d10_thr12` 是当前较平衡的默认候选：
  - ROI 尺寸变大
  - 候选数量不过度膨胀
  - 后续仍由 manual GUI 人工挑选，不依赖 suite2p iscell

- 05 默认参数改为：
