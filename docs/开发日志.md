# 开发日志

## 2026-07-01

### 前半段 pipeline 兼容无 analog / 无刺激记录 setup

- 修改文件：
  - `current/preprocess/02_generate_stim_map.py`
  - `README.md`
- 修改目的：
  - 把 pipeline 到 `manual` 为止的部分从“默认假设有 stim analog”改成“stim analog 可选、外部刺激记录可选”的更通用入口。
  - 让别人即使没有你的 analog 通道，下载代码后也能先跑通 `premanual -> manual`。
- 主要改动：
  - step 02 的 trial 发现逻辑不再只扫描 `*_Stim_Analog.tif`，现在只要 step 01 目录里有 `*_metadata.json`，即使没有 analog 文件，也会把该 trial 纳入处理。
  - 当 trial 没有 projected stim analog，也没有完整 raw stim analog 时，step 02 会生成 `no_analog_input` 的零轨迹兼容输出，而不是直接把 trial 判定为不存在。
  - 如果外部刺激日志存在且能用 metadata 的采集开始时间匹配到协议，step 02 仍会输出 protocol-time fallback 的 `stim_events`。
  - 如果既没有 analog 也没有外部刺激日志，则 step 02 会明确写出 `nostim` 兼容 sidecar，保证 03–05 和 manual GUI 还能继续使用。
  - README 增加了“到 manual 为止兼容三类 setup”的说明，以及 step 01/02 的最小必要输入边界。
- 主要结果：
  - `premanual` 前半段不再把“有 analog 通道”当作 trial 是否存在的前提。
  - 同一套前处理现在可以同时覆盖有刺激、无 analog 但有协议、完全无刺激三种场景。
- 可能影响：
  - step 02 汇总里会出现 `no_analog_input` / `nostim` trial；这是预期行为，不表示失败。
  - `manual` 之前的通路更通用了，但 `06` 之后的 stimulus-locked 分析仍然只有在确实有可解释的刺激时间时才有意义。
- 后续注意事项：
  - 如果后面要继续把 06 之后也做成“别人下载就能直接用”，还需要再梳理哪些分析步骤应在 `nostim` trial 自动降级或跳过。
  - 如果要同步到工作站，先 dry-run 检查 `current/preprocess/02_generate_stim_map.py` 和 `README.md` 的覆盖范围即可。

## 2026-06-25

### 生成 calcium imaging pipeline 可编辑流程图

- 生成文件：
  - `docs/figures/calcium_imaging_pipeline_flowchart.pptx`
  - `docs/figures/calcium_imaging_pipeline_flowchart.svg`
- 生成目的：
  - 根据 `README.md` 中的 pipeline 总览与步骤说明，制作一张可直接放入组会 PPT 的 16:9 方法流程图。
  - PPTX 中所有节点、文字、小示意图和箭头均为可编辑 PowerPoint shape / text / connector，不使用 PNG/JPG 作为最终图。
- 主要设计逻辑：
  - 按 `Premanual -> Manual -> Postmanual` 三段上下排列，每段内部按步骤横向连接。
  - 明确区分 `05 ROI candidate detection` 与 `Manual ROI curation`：自动步骤只生成候选 ROI，人工校对是唯一决定 final ROI set 的节点。
  - `06 dF/F extraction` 画为从 final ROI set 和 motion-corrected movie 重新提取 fluorescence，而不是沿用 suite2p detection trace。
  - `08 Stimulus response` 使用 stim map 做 trial alignment 和 response heatmap。
  - `09 AoLP tuning` 标注 AoLP 为 180° 周期 axial data。
  - `10-16 Population analysis` 合并为 ROI-level dashboard block，表示 trace QC、feature table、similarity matrix、hierarchical clustering、Leiden graph 和 PCA/UMAP，不表示重新做 ROI detection。
- 后续可编辑注意事项：
  - 在 PowerPoint 中可直接编辑文字、移动节点、修改颜色和箭头。
  - 若后续 README 的步骤编号、命名或依赖关系变化，应同步更新 PPTX 与 SVG 两个版本。
  - 本次只生成流程图和日志，不运行真实数据，也不读取大型 OIR / TIFF / movie / NPY 文件。
- 是否需要同步到工作站：
  - 需要时可将 `docs/figures/` 和本日志同步到 Linux 工作站；同步前建议先做 dry-run，避免覆盖远程未同步修改。
